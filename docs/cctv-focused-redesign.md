# CCTV 중심 공개 화면 — 검토용 변경

## 범위

- `/`, `/cctv`, `/search`에서 동일한 CCTV 탐색 화면을 사용한다. 검색어·방향·종류·지도/목록 상태는 URL에 남는다.
- 공개 헤더는 CCTV 목록, 지도, 멀티뷰와 기존 로그인만 노출한다. 기존 사이드바/하단 메뉴/전역 챗봇/서비스 공지는 삭제하지 않고 숨긴다.
- 기존 홈·검색·CCTV 화면은 `components/legacy/`에 그대로 보존한다. `constants/public-features.ts`의 `CCTV_FOCUSED_PUBLIC`을 false로 바꾸면 이전 화면/탐색 메뉴를 복원할 수 있다. 기능·API·기존 URL·인증은 제거하지 않는다.
- 카메라 원본 데이터, `constants/mock-cctvs.ts`, `locations.json`은 보존한다. 프록시의 공개 설정 갱신·차단 로직은 별도 검토용 코드로 보완하며, 원본 목록·계정·서버 자원·구독 설정은 삭제하지 않는다.
- 목록에서는 실제 재생하지 않는다. `LIVE`나 `연결됨`을 추정 표시하지 않으며, 카메라를 선택한 뒤 플레이어가 관측한 재생 상태만 보여준다.
- Firestore 공개 목록이 비어 있거나 실패하면 빈 상태/연결 오류를 표시한다. 목 데이터를 실제 공개 카메라처럼 되살리지 않는다. 비활성·목 데이터 대체 상세 페이지는 장소/URL만 남기고 재생하지 않는다.
- 지도는 기존 Kakao Maps 설정을 유지한다. YouTube/HLS/기존 HTTP 새 창을 구분하고, 키 누락·로딩 실패·위치 없는 상태를 안내한다. 모달 닫기와 페이지 이동 시 플레이어를 정리한다.

## 정상 재생 판단과 오류

- HLS: 디코딩된 영상 크기가 있고 미디어 시간이 실제 진행되어야 재생으로 판단한다. 20초 시작 지연/멈춤은 임시 오류로 바뀌고 수동 재시도를 제공한다. 탭 숨김/사용자 일시 정지는 카메라 고장으로 판단하지 않는다.
- YouTube: 공식 iframe API의 재생 상태·시간 진행과 오류 이벤트를 이용한다. iframe 준비 완료는 재생 성공이 아니다. 자동재생 제한에는 재생 버튼, 제공자 오류에는 재시도/원본 링크를 제공한다.
- `/api/cctv/health`는 HTTP 전송 진단만 반환한다. `reachable`은 영상 재생 증거가 아니며 항상 `playbackVerified:false`다. 예전 `ok:true`를 정상 영상으로 오해하지 않도록 `ok:false`를 유지한다. 이 API는 카메라 전역 고장 판정이나 관리자 자동 승인이 아니다.
- 시청자 단일 실패로 카메라를 영구 비활성화하거나 Firestore에 개별 심박 기록을 쓰지 않는다. 현재 창의 임시 오류 안내 + 관리자의 명시적인 비활성화/승인 방식을 사용한다.
- 정상 재생은 이 브라우저의 미디어 진행을 뜻한다. 촬영 시각의 최신성, 실제 현장과의 일치, 모든 이용자의 가용성은 별도 확인 대상이다.

## 관리자 검토

`docs/cctv-admin-review.md` 참조. 기존 공개 카메라는 일괄 중단하지 않는다. 신규/소스 변경만 보류하며, 정확한 저장 소스의 관리자 관찰 후 승인한다. 신규·비활성 HTTP 카메라의 인증된 자동 미리보기는 기존 인프라로 지원되지 않으므로 호환 가능한 승인된 환경에서 수동 확인하거나 보류해야 한다.

## 검증/검토 조건

- `npm run test:cctv` (Node 22.6 이상/검증 환경 Node 24): 순수 필터·재생 관찰·관리자 승인 정책 테스트.
- `npm run type-check`, 변경 파일 ESLint, `git diff --check`.
- 전체 `npm run lint`에는 기존 오류가 남아 있으므로 전체 통과로 표시하지 않는다.
- `npm run build`는 번들/TypeScript 이후 Firestore 자격증명이 필요한 페이지 프리렌더에서 중단될 수 있다. 실제 스테이징 환경에서 전체 빌드를 다시 검증한다.
- 브라우저 QA: 모바일/데스크톱, 검색·방향·종류 조합, 빈 결과, 지도/목록 전환, 반복 열기/닫기·Escape·뒤로/앞으로, 로그인 취소/복귀, 영상 중단/오류/재시도, 관리자 소스 수정 후 이전 승인 거부.
- 원본 디자인 이미지 접근과 브라우저 실측 검증이 완료되지 않았다. 현재 스타일은 문자로 제공된 제주 에디토리얼 방향을 바탕으로 한 검토용 구현이며 시안과 일치한다고 주장하지 않는다.

## 배포 전 확인

실제 Firestore/KV 관리자 통합 검증과 카메라 실재생·YouTube·iOS Safari/팝업·CORS 검증이 필요하다. 이 패치는 배포/원격 push, 인프라 변경, 카메라 데이터 쓰기, 결제/구독 해지를 수행하지 않는다. Vultr·Cloudflare는 다른 기능/프로젝트 의존 확인 및 사용자 확인 전 유지한다.

## 검토 보완: 데이터 장애와 ISR 캐시

카메라 단건 조회는 `found`, `missing`, `unavailable`을 구분한다. 실제 문서가 없다는 확인을 받은 경우에만 기존 URL용 비활성 메타데이터를 사용한다. Firestore 연결/권한/설정 오류는 카메라 비활성 판정으로 바꾸지 않고 페이지·메타데이터에서 예외를 전파한다. 오류 경계는 정보 연결 문제임을 설명하고 재조회한다. 정상 결과의 기존 영구 캐시 정책은 유지하되 실패를 성공 HTML로 저장하지 않는다.

회귀 테스트는 실제 상세 페이지가 예외를 전파하는지와 설치된 Next 16.2.7 `ResponseCache`가 초기 오류를 저장하지 않고, 재생성 오류에서는 이전 성공 결과와 제한된 재시도 간격을 유지한 뒤 정상 조회로 복구하는지를 검증한다. 실제 배포 CDN 통합 검증과는 구분한다. 프레임워크의 오류 재검증 동작은 [Next.js ISR 안내](https://nextjs.org/docs/app/guides/incremental-static-regeneration#handling-uncaught-exceptions)에도 설명되어 있다.

## 검토 보완: 프록시 공개 설정 동기화

`vultr-proxy/server.js`는 인증된 정상 빈 객체 `{}`를 공개 카메라 0개로 수용한다. HTTP 실패·잘못된 JSON/스키마는 이전 정상 상태를 유지한다. ADMIN_SECRET이 설정된 구성 관리 모드는 첫 정상 조회 전 비공개로 시작하며, 인증 설정 없는 기존 정적 수동 모드는 별도로 유지한다. 제거/소스 변경 시 캐시·릴레이·허용 URL을 정리하고, 진행 중 응답도 소스 버전이 맞지 않으면 버린다. 현재 승인된 재생목록이 실제 광고한 조각 URL만 허용하므로 정당한 다른 CDN 주소는 지원하고 임의/이전 주소 재생은 막는다.

이 코드는 Vercel 웹앱 배포만으로 운영 중인 Vultr Node 프로세스에 반영되지 않는다. 별도의 안전한 서버 배포·검증이 필요하다. 5분 설정 갱신 간격은 유지한다. 이미 열린 직접 원본 팝업에 전달된 외부 URL이나 브라우저에 다운로드된 데이터까지 소급 회수할 수는 없다.

현재 소스가 광고한 child playlist는 미디어 조각 1,000개 제한과 별도로 보관한다. root 조회 때 원본 session URL이 바뀌어도 기존 시청자의 playlist는 마지막 광고/사용 후 60초 동안 유지하고, 실제 사용 시 갱신한다. 카메라별 활성 playlist는 최대 256개이며 한도를 넘으면 기존 활성 session을 퇴출시키지 않고 새 응답을 실패시킨다. 다른 session/화질 URL은 같은 내용이라고 가정하지 않고 정확한 URL별 캐시·진행 중 요청 키를 사용한다(재생목록 캐시 전체 512개 제한). 비공개/소스 변경은 idle 만료를 기다리지 않고 권한과 캐시를 정리한다. 이 메모리 제한·60초 유휴 정책은 실제 카메라의 target duration/동시 시청 규모에 맞춘 스테이징 검증이 필요하다.
