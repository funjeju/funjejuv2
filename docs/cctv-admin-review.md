# CCTV 검토 / 게시

- 기존 카메라와 URL은 삭제하지 않는다. 삭제 버튼은 비활성화로 대체한다.
- 새 카메라 또는 영상 주소/YouTube ID 변경은 비활성 상태로 저장한다.
- 제목·설명 등 메타데이터만 수정하면 기존 공개 상태를 유지한다.
- 시딩은 기존 문서를 덮어쓰지 않으며, 없는 카메라만 비활성으로 추가한다.
- 목록의 `재생 검토 / 승인`에서 저장된 소스를 실제로 확인한다. 원본 장소와 소스가 일치하고, 영상/시간이 10초 이상 진행하는지 확인한다. 오류, 검은 로딩 화면, HTTP 성공만으로 승인하지 않는다.
- HTTP 소스는 HTTPS 문서에 삽입하지 않는다. 신규·비활성 소스는 기존 뷰어 공개 설정에 없으므로 자동 미리보기할 수 없다. 저장된 정확한 원본 링크를 새 창으로 열어 네이티브 HLS 지원 브라우저 또는 승인된 운영 환경에서 수동 확인한다. 재생 가능한 환경이 없다면 검토 미지원 상태로 보류한다. 별도 인증된 HTTP 미리보기 서버는 이 변경에 포함되지 않는다. 기존 공개 카메라에만 기존 HTTP 뷰어 링크를 제공한다. 기존 뷰어 설정 갱신은 즉시가 아니므로 정확한 저장 소스인지 확인하지 못하면 보류한다. 브라우저의 혼합 콘텐츠/CORS/팝업 제한은 우회하지 않는다.
- 승인은 **관리자가 관찰했다는 명시적 기록**이며, 서버가 영상을 디코딩했다는 인증이 아니다. API는 인증된 관리자, 정확한 소스 리비전(SHA-256), 명시적 관찰 확인, 15분 이내 기록을 요구한다. 소스가 변경되면 이전 관찰로 승인할 수 없다.
- YouTube가 선택되어 있으면 남아 있는 originUrl은 HLS 게시 근거가 아니다. 저장·이름 수정·승인·비활성화 모두 기존 HLS KV 항목을 제거하고 Firestore의 원본 주소/카메라 기록은 보존한다. 정리 실패는 proxySyncPending으로 기록하며, 승인은 보류하고 비활성화는 유지한다.
- Worker 또는 KV 통합 설정이 있으면 필요한 KV 동기화/정리 성공 후에 활성화한다. 자격증명이 없거나 실패하면 승인을 보류한다. Worker 없는 기존 프록시 구성은 유지한다.
- 비활성화는 Firestore부터 즉시 처리하고 동기화 오류를 표시한다. 원격 캐시/기존 플레이어 반영에는 지연이 있을 수 있다.

## 검증 범위

`node --test tests/cctv-admin-api.test.mjs tests/cctv-review.test.mjs`는 인증 거절, 게시 상태 주입 방지, 관찰 없는 게시 거절, KV 실패, HLS→YouTube 전환 후 이름 수정/비활성화의 잔존 HLS 재활성화 방지, 자격증명 누락 시 보류, 동시 수정 / 커밋 실패 시 보상 복구까지 외부 연결 없는 경계 모킹으로 검증한다. 순수 정책 테스트는 리비전, 관찰 유효기간, HTTP 신호의 비인증성, 저장 시 공개 상태 보존을 검증한다. 인증된 실제 Firestore 쓰기, Cloudflare KV 동기화, 외부 카메라 재생 및 브라우저 UI는 별도 스테이징 검증이 필요하다. 이 변경 과정에서 실서비스 데이터/인프라를 변경하지 않았다.

## 알려진 경계

Firestore와 외부 KV는 하나의 원자적 트랜잭션이 아니다. API는 게시 직전에 Firestore 소스 리비전과 문서 수정 시각을 다시 검사한다. 충돌 / 커밋 실패 시 최신 문서로 KV를 복구(소스 제거 시 KV 삭제)하고 승인을 취소한다. 복구 실패는 문서의 proxySyncPending에 기록하고 관리자 목록에 동기화 보류로 표시한다. 복수 관리자가 같은 카메라를 동시에 수정하거나 원격 동기화가 실패한 경우, 오류를 해결하고 정확한 공개 소스를 재검토해야 한다. 기존 공개 Firestore 읽기 규칙은 그대로이므로 비활성은 비밀 문서 보관 기능이 아니다. 소스에 비밀 토큰을 넣지 않는다.

`/api/proxy-config`도 선택된 YouTube 소스의 남겨둔 HLS 주소를 활성 프록시 설정으로 출력하지 않는다. Firestore 기록과 기존 URL 문자열은 보존한다. 이 앱 쪽 출력 수정이 원격 서버 캐시를 즉시 비우거나 기존 접속을 끊는다는 뜻은 아니다. 함께 제공되는 Vultr 보완 코드는 정상 빈 설정을 반영하고 제거된 카메라의 캐시/조각 경로를 차단한다. 실제 별도 서버 반영과 폴링 지연은 스테이징에서 확인해야 하며, 인프라 변경/해지는 별도 확인 없이 실행하지 않는다.

### 동시 저장 / 비활성화 시 동기화

저장(POST), 비활성화 및 승인 실패 보상은 공통 `reconcileLatest` 경로를 사용한다. 현재 문서 스냅샷을 읽고 해당 상태를 KV에 반영한 뒤, Firestore 트랜잭션에서 **동일 updateTime**인지 확인한 경우에만 동기화 보류 표시를 해제한다. 그 사이 변경되면 최신 문서로 최대 3회 다시 반영한다. 두 번째 보상 중 다시 변경되는 경우도 같은 검증을 거친다. 최신 상태를 확정하지 못하거나 쓰기 검증이 실패하면 성공으로 처리하지 않고 `proxySyncPending:true` 및 경고를 남긴다. Firestore 자체가 쓰기 불가하면 표시 저장도 실패할 수 있으므로 응답 경고를 기준으로 점검해야 한다.

이 검사는 두 저장소를 원자적으로 만들지는 않는다. 요청 수행 중 잠깐의 원격 불일치 및 프로세스 중단 시 미완료 보상 가능성이 남는다. 운영 중 보류 항목을 재확인해야 하며, 강한 전달 보장이 필요하면 별도 영속 작업 큐/재조정 작업이 필요하다. 이 변경에서는 인프라를 추가하지 않는다.
